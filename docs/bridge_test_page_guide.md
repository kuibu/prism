# 桥接测试页面操作说明（超易懂版）

这份说明是给“第一次用也能跑通”的用户写的。

## 0. 先理解它是做什么的

桥接测试页面做的事很简单：
- 左边是 Matrix 房间（你自己的聊天房间）
- 右边是外部 App（Telegram、WhatsApp、Slack 等）
- “桥接”就是把两边消息互相转发

在这个 MVP 里，外部 App 用“模拟消息”来测流程。

## 1. 一分钟上手（最短路径）

1. 打开 [http://localhost:8080/web/](http://localhost:8080/web/)
2. 先注册/登录
3. 创建一个房间并进入（拿到 `room_id`）
4. 打开 `桥接测试` Tab
5. 选择平台（建议先选 Telegram）
6. 点 `创建连接器`
7. 填 `外部会话 ID`，点 `创建桥接映射`
8. 在“消息中继测试”里输入“外部发送者+消息内容”，点 `模拟入站`
9. 切回聊天页，应该看到桥接消息

你已经跑通一次桥接链路。

## 1.1 真实 Telegram 联调（需要一个 Telegram Bot）

如果你要跟真实 Telegram App 联调，请按这组步骤：

1. 在 Telegram 里找 `@BotFather`
2. 发送 `/newbot` 创建机器人，拿到 `Bot Token`
3. 把这个 bot 拉进你要测试的 Telegram 群
4. 拿到该群的 `chat_id`（常见形态是 `-100...`）
5. 回到本页面的 `桥接测试`：
 - 平台选 `Telegram`
 - 创建连接器时填好名称、方向（建议双向）
 - 在 `Telegram 真实联调` 区填 `Bot Token`
 - `外部会话 ID` 填群的 `chat_id`
 - 创建桥接映射
6. 测 Telegram -> Matrix：
 - 在 Telegram 群里发一句话
 - 回页面点 `拉取 Telegram 新消息（真实）`
 - 去聊天页看是否进了 Matrix 房间
7. 测 Matrix -> Telegram：
 - 在 Matrix 聊天页发一句话
 - 回桥接页点 `发送到 Telegram（真实）`
 - 去 Telegram 群确认收到消息

如果第 6 步能通，说明“入站”通了；第 7 步能通，说明“出站”通了。

## 2. 页面里每一块是干什么的

## 2.1 Bridge 连接器

作用：定义“接哪个外部平台”。

关键字段：
- `桥接平台`: Telegram / WhatsApp / Slack / Discord / WeCom / Signal / Custom
- `桥接方向`: 仅入站 / 仅出站 / 双向
- `密钥引用`: 例如 `telegram_bot_token`（只是引用名，不直接把密钥写在页面里）

## 2.2 Bridge 房间映射

作用：把“外部会话”绑定到“Matrix 房间”。

关键字段：
- `桥接连接器`: 选你刚创建的连接器
- `当前房间 ID`: Matrix 的 `!room:localhost`
- `外部会话 ID`: 外部 app 的群/频道/会话 ID
- `外部会话名称`: 人类可读名字（可选）

## 2.3 Bridge 消息中继测试

作用：做两种验证。

- `模拟入站`：外部 -> Matrix
- `预览出站`：Matrix -> 外部（先预览 payload，不直接发到外部）

## 3. 现在 UI 会“跟平台联动”

你切平台后，页面会自动变化：
- 方向下拉只显示该平台支持的方向
  - 例如 WhatsApp / Signal 默认只给“入站、出站”，不会给双向
- `外部会话 ID`、`外部发送者`、`密钥引用` 的示例占位会变
  - Telegram 会提示 chat_id（常见 `-100...`）
  - WhatsApp 会提示群组或号码格式
  - Slack 会提示 `C...` channel id
- 中继按钮会带平台名
  - 例如“模拟入站（Telegram）”
- 如果连接器方向不支持某动作，按钮会禁用并显示原因
  - 例如“仅出站”时，会禁用“模拟入站”

这样做的目的：减少误操作，让页面行为更像你选中的目标 App。

## 4. 给奶奶的排错小抄

如果点按钮报错，先看下面这几条：

1. 没登录
- 现象：接口报未授权
- 处理：先去“注册/登录”页登录

2. 没选房间
- 现象：提示需要房间 ID
- 处理：先创建/加入房间，再回桥接页

3. 没建映射
- 现象：入站报找不到 link
- 处理：先在“Bridge 房间映射”创建一条映射

4. 方向不匹配
- 现象：入站或出站按钮灰掉，或者报“不支持该方向”
- 处理：把连接器改成支持该动作的方向

5. 看不到新消息
- 处理：切到聊天页点一次同步，或等自动同步

## 5. 产品设计检查结论（本次更新）

已修正的问题：
- 之前不同平台 UI 几乎不变，用户不知道不同平台字段怎么填
- 之前方向和动作不联动，容易点了才报错
- 之前按钮文案不带平台，测试时容易混淆

本次已改：
- 平台切换联动字段提示
- 平台能力联动方向选项
- 连接器方向联动动作可用性（禁用+提示）
- 按钮文案带平台名称
- 增加 Telegram 真实联调区（真实拉取 + 真实发送）

仍保留（合理）：
- 这是“桥接测试页”，不是最终生产运营台，所以以“可验证链路”为主，不做复杂运营配置
