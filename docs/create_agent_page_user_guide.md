# 创建 Agent 页面使用说明

## 1. 文档目标
- 这份文档用于指导你在 Web 前端的 `创建 Agent` 页面完成数字秘书与专用 Agent 的日常操作。
- 适用于当前项目页面：`http://localhost:8080/web/`。

## 2. 使用前准备
1. 服务已启动：`docker compose up -d --build`。
2. 你已在页面里完成注册/登录。
3. 最好已有至少一个房间（便于后续采集记忆与运行技能）。

## 3. 页面结构总览
`创建 Agent` 页面主要分为 6 个区块：
1. `初始化区`：初始化秘书体系、加载 Agent、加载技能目录。
2. `数字秘书 Agent`：维护秘书资料、授权、采集记忆、运行日报。
3. `大模型接入配置`：给秘书配置 LLM（provider/model/key/base_url/api_path）。
4. `专用 Agent`：创建多个专用 Agent，并绑定到秘书。
5. `Agent 记忆`：检索、查看最近记忆、手动新增记忆笔记。
6. `技能运行与兼容能力`：运行技能、授权/撤权、摘要操作（兼容旧入口）。

## 4. 推荐操作顺序（新用户）
1. 点击 `初始化秘书与Agent体系`。
2. 点击 `加载我的Agent` 和 `加载技能目录`，确认页面加载成功。
3. 在 `数字秘书 Agent` 区填写/确认秘书 Purpose（默认可直接用）。
4. 在 `大模型接入配置` 区确认模型参数。
5. 点击 `保存数字秘书资料`。
6. 点击 `给数字秘书授权`。
7. 点击 `采集消息到秘书记忆`。
8. 点击 `运行秘书日报` 验证秘书链路。
9. 如需专用机器人，在 `专用 Agent` 区创建专用 Agent 并做快速运行。

## 5. 各区块详细说明

### 5.1 初始化区
按钮：
- `初始化秘书与Agent体系`
- `加载我的Agent`
- `加载技能目录`

作用：
- 初始化会保证每个用户有一个默认数字秘书 Agent。
- 加载操作会刷新本页下拉框和表格数据。

常见提示：
- 成功：会弹出 “Agent 列表已刷新/技能目录已刷新”。
- 失败：通常是未登录或网关服务异常。

### 5.2 数字秘书 Agent 区
主要字段：
- `数字秘书 ID`：秘书的唯一标识。一般初始化后自动填好。
- `秘书执行 Purpose`：秘书执行任务时使用的业务目的（如 `secretary_collect`）。
- `秘书采集 Purpose`：采集记忆时使用的目的，建议与授权 purpose 保持一致。
- `每分钟限流`：授权时的速率限制。

主要按钮：
- `保存数字秘书资料`
- `给数字秘书授权`
- `采集消息到秘书记忆`
- `运行秘书日报`

建议：
- 如果后续出现 `403 denied`，优先检查是否先授权、purpose 是否一致、是否被撤权。

### 5.3 大模型接入配置区（秘书）
字段说明：
- `启用大模型`：开关。
- `模型服务商`：支持 `openrouter`、`qwen`、`openai_compatible`。
- `模型名称`：例如 `qwen2.5-32b`。
- `API Key`：按服务商要求填写。
- `API Base URL`：兼容 OpenAI 的地址。
- `API Path`：通常 `/chat/completions`。

注意：
- 本项目默认可走 openai-compatible 端点。
- 修改后要点 `保存数字秘书资料` 才会写入后端 Agent 配置。

### 5.4 专用 Agent 区
目标：
- 创建多个专用 Agent（如待办专员、会议专员）。
- 每个专用 Agent 自动绑定到当前用户的秘书（受秘书管理）。

主要字段：
- `专用Agent名称`
- `专用Agent Purpose`
- `专用Agent技能`
- `房间范围（逗号分隔）`
- 专用 Agent 的 LLM 配置（与秘书同结构）

主要按钮：
- `创建专用Agent`
- 表格内 `运行技能`
- 表格内 `采集记忆`

### 5.5 Agent 记忆区
能力：
- `检索记忆`：按关键词查找。
- `查看最近记忆`：按时间查看最新记忆。
- `新增记忆笔记`：人工写入高价值记忆。

关键字段：
- `记忆所属Agent` 必填。
- `记忆检索词` 可选。
- `记忆返回条数` 建议 20 左右。

### 5.6 技能运行与兼容能力区
这是兼容旧流程的通用区，常用于调试：
- `创建 Agent 资料`（本地展示/兼容）
- `授权 Agent`
- `撤销授权`
- `摘要（仅返回）`
- `摘要并发送到房间`
- `运行技能`

建议：
- 生产使用思路上更推荐“秘书优先 + 专用 Agent 附属”的流程。
- 该区保留用于快速联调和回归测试。

## 6. 典型场景示例

### 6.1 场景 A：初始化并跑通秘书
1. 点击 `初始化秘书与Agent体系`。
2. 点击 `保存数字秘书资料`。
3. 点击 `给数字秘书授权`。
4. 点击 `采集消息到秘书记忆`。
5. 点击 `运行秘书日报`。
6. 在页面底部输出框确认返回 `status: ok`。

### 6.2 场景 B：创建一个“待办专员”
1. 在 `专用 Agent` 区填：
- 名称：`待办专员`
- Purpose：`todo_followup`
- 技能：`specialist.todo_extractor`
2. 点击 `创建专用Agent`。
3. 在表格中对该 Agent 点 `运行技能` 验证输出。

### 6.3 场景 C：撤权验证
1. 在兼容区执行一次 `授权 Agent`。
2. 运行一次技能确认可用。
3. 点击 `撤销授权`。
4. 再次运行技能，应出现 403 deny（预期行为）。

## 7. 常见问题与排查

1. `No active session`
- 原因：未登录。
- 处理：先去 `注册 / 登录` 页面登录。

2. `403 denied`
- 原因：未授权、授权被撤销、purpose 不匹配、触发限流。
- 处理：检查授权状态与 purpose 是否一致；必要时重新授权。

3. `422` 参数校验失败
- 原因：必填字段缺失或格式错误。
- 处理：按字段提示补齐，重点检查 `Agent ID/Purpose/room_id`。

4. 大模型没有生效
- 原因：未启用开关、配置未保存、provider/base_url/model 不匹配。
- 处理：检查配置后点 `保存数字秘书资料` 或重新创建/更新专用 Agent。

## 8. 与聊天页面的关系
- `创建 Agent` 页负责“配置与管理”。
- 真正的秘书联动（房间模式 `auto/semi/off`、建议审批、侧栏分析）主要在聊天页右侧进行。
- 推荐做法：先在 `创建 Agent` 页把权限和模型配好，再到聊天页做联动测试。

## 9. 最佳实践
1. 每次修改 LLM 参数后先做一次技能运行烟测。
2. purpose 命名统一，避免授权和调用不一致。
3. 专用 Agent 数量多时，按用途拆分，避免一个 Agent 承担过多职责。
4. 关键操作后去审计页做一次查询与验链，确认安全闭环可追溯。
